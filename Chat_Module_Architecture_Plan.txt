1. EXECUTIVE OVERVIEW & OBJECTIVES
--------------------------------------------------------------------------------
Phase 4 introduces a modern, WhatsApp-inspired local messaging and team
collaboration module into the "My Workspace" Android productivity platform.

Key Tenets:
1. Distinct Original Identity:
   - Inspired by the fluid interaction patterns of WhatsApp (conversation lists,
     message bubbles, delivery ticks, quote replies, attachment menus).
   - Styled strictly in the "My Workspace" design language: Electric Blue and
     Royal Violet accents, Slate Surface dark surfaces, AMOLED black compatibility,
     modern typography, and rounded Material 3 cards.
   - Absolutely no WhatsApp branding, green logos, or copyright infringements.
2. Complete Offline-First & Local Persistence:
   - Local Room SQLite database serves as the single source of truth.
   - Works 100% offline with zero external network or server dependencies.
   - Transparently framed as local workspace collaboration without claiming
     simulated messages are live online network transmissions.
3. Strict Preservation of Existing Modules:
   - Zero breaking changes to Phase 1 (UI & Theming), Phase 2 (Core Storage),
     or Phase 3 (Task Dependencies, Hierarchies, Progress Engine).
   - Database migrated from version 3 to 4 with non-destructive table additions.


2. EXISTING ARCHITECTURE AUDIT & FINDINGS
--------------------------------------------------------------------------------
• Architecture Pattern: MVVM + Clean Architecture + Repository Pattern.
• Language & UI: 100% Kotlin + Jetpack Compose (Material 3).
• Dependency Injection: Constructor Injection + ViewModelFactory (`WorkspaceViewModelFactory`).
• Single Activity: `MainActivity.kt` with `enableEdgeToEdge()` and centralized theme.
• Navigation:
  - `Screen.kt` defines sealed class routes.
  - `Navigation.kt` hosts `MainNavigation` with a 5-item Bottom Bar (`Home`, `Projects`,
    `Tasks`, `Calendar`, `More`).
  - Secondary screens (`ProjectDetail`, `TaskDetail`, `Kanban`, `Analytics`, `Notes`,
    `Search`, `Backup`, `Settings`) are stacked inside `NavHost`.
• Current Room Database:
  - File: `/app/src/main/java/com/example/data/local/database/WorkspaceDatabase.kt`
  - Current Version: **3**
  - Existing Tables (9): `categories`, `projects`, `tasks`, `checklist_items`,
    `comments`, `progress_logs`, `notes`, `activity_logs`, `task_dependencies`.
  - Type Converters: `DatabaseConverters.kt` (Date, List<String>, Map).
• Current ViewModel:
  - `WorkspaceViewModel.kt`: Centralized reactive state flows (`allTasks`, `activeProjects`,
    `blockedTaskIds`, `dashboardStats`, `themeMode`).

5. DATABASE SCHEMA & MIGRATION PLAN (v3 -> v4)
--------------------------------------------------------------------------------

5.1 New Room Entities:

1. `conversations` table (`ConversationEntity`):
   - `id`: TEXT PRIMARY KEY (UUID)
   - `title`: TEXT NOT NULL (Contact name or Channel title)
   - `isGroup`: INTEGER NOT NULL (0 = Direct 1-on-1, 1 = Group/Channel)
   - `avatarUrl`: TEXT NULL
   - `avatarColor`: TEXT NOT NULL (Hex string for generated avatar fallback)
   - `contactId`: TEXT NULL (Reference to contacts table)
   - `isPinned`: INTEGER NOT NULL DEFAULT 0
   - `isMuted`: INTEGER NOT NULL DEFAULT 0
   - `unreadCount`: INTEGER NOT NULL DEFAULT 0
   - `lastMessageId`: TEXT NULL
   - `lastMessageText`: TEXT NULL
   - `lastMessageTimestamp`: INTEGER NOT NULL
   - `createdAt`: INTEGER NOT NULL
   - `updatedAt`: INTEGER NOT NULL

2. `chat_messages` table (`ChatMessageEntity`):
   - `id`: TEXT PRIMARY KEY (UUID)
   - `conversationId`: TEXT NOT NULL, FOREIGN KEY -> `conversations(id)` ON DELETE CASCADE
   - `senderId`: TEXT NOT NULL ("me" or contactId)
   - `senderName`: TEXT NOT NULL
   - `text`: TEXT NOT NULL
   - `messageType`: TEXT NOT NULL ("TEXT", "IMAGE", "DOCUMENT", "AUDIO", "VOICE_NOTE")
   - `status`: TEXT NOT NULL ("SENDING", "SENT", "DELIVERED", "READ")
   - `replyToMessageId`: TEXT NULL
   - `replyToSenderName`: TEXT NULL
   - `replyToText`: TEXT NULL
   - `isStarred`: INTEGER NOT NULL DEFAULT 0
   - `isDeletedForEveryone`: INTEGER NOT NULL DEFAULT 0
   - `createdAt`: INTEGER NOT NULL
   - `updatedAt`: INTEGER NOT NULL

3. `message_attachments` table (`MessageAttachmentEntity`):
   - `id`: TEXT PRIMARY KEY (UUID)
   - `messageId`: TEXT NOT NULL, FOREIGN KEY -> `chat_messages(id)` ON DELETE CASCADE
   - `fileName`: TEXT NOT NULL
   - `fileUri`: TEXT NOT NULL
   - `fileType`: TEXT NOT NULL ("image/jpeg", "application/pdf", etc.)
   - `fileSizeBytes`: INTEGER NOT NULL
   - `thumbnailUri`: TEXT NULL
   - `durationMs`: INTEGER NULL (for voice/audio)
   - `createdAt`: INTEGER NOT NULL

4. `contacts` table (`ContactEntity`):
   - `id`: TEXT PRIMARY KEY (UUID)
   - `name`: TEXT NOT NULL
   - `role`: TEXT NOT NULL
   - `email`: TEXT NULL
   - `avatarColor`: TEXT NOT NULL
   - `initials`: TEXT NOT NULL
   - `statusBio`: TEXT NOT NULL
   - `isOnline`: INTEGER NOT NULL DEFAULT 0
   - `lastSeenTimestamp`: INTEGER NOT NULL
   - `createdAt`: INTEGER NOT NULL

5.2 Database Indexes:
• `index_chat_messages_conversationId` ON `chat_messages(conversationId)`
• `index_chat_messages_createdAt` ON `chat_messages(createdAt)`
• `index_conversations_lastMessageTimestamp` ON `conversations(lastMessageTimestamp)`
• `index_conversations_isPinned` ON `conversations(isPinned)`
• `index_message_attachments_messageId` ON `message_attachments(messageId)`

5.3 Migration Plan (`MIGRATION_3_4`):
• Safe SQLite DDL using `CREATE TABLE IF NOT EXISTS` and `CREATE INDEX IF NOT EXISTS`.
• Increments `WorkspaceDatabase` version from `3` to `4`.
• Default seed data injection for pre-populated workspace colleagues (e.g. Design Lead,
  Engineering Lead, Project Manager) so the chat interface immediately displays
  meaningful conversation threads upon launch.


6. NAVIGATION INTEGRATION PLAN
--------------------------------------------------------------------------------
To seamlessly integrate Chat without breaking the existing 5 bottom navigation tabs
(`Home`, `Projects`, `Tasks`, `Calendar`, `More`):

1. Primary Ubiquitous Access Points:
   - `AppTopBar.kt`: Add a Chat icon button with a live unread badge counter next to
     the Notifications and Search icons on the Dashboard.
   - `DashboardScreen.kt`: Add a "Workspace Messages" quick card previewing recent
     chats and direct shortcut to start a chat.
   - `MoreScreen.kt`: Add a "Team Chat & Collaboration" list item under Communications.

2. Navigation Routes in `Screen.kt`:
   - `object Chats : Screen("chats")`
   - `object Conversation : Screen("conversation/{conversationId}") { fun createRoute(id: String) = "conversation/$id" }`
   - `object ConversationDetail : Screen("conversation_detail/{conversationId}") { fun createRoute(id: String) = "conversation_detail/$id" }`

3. Bottom Bar Behavior:
   - `ChatsScreen` can optionally hide the bottom bar or retain it depending on whether
     navigated from bottom nav or top bar. When entering an individual `ConversationScreen`,
     the bottom bar is hidden to maximize screen real estate for the message thread and composer.

8. PERMISSIONS & DEPENDENCIES AUDIT
--------------------------------------------------------------------------------
• Permissions:
  - Zero broad storage permissions (`READ_EXTERNAL_STORAGE` or `WRITE_EXTERNAL_STORAGE` are FORBIDDEN).
  - Use modern Android Photo Picker (`ActivityResultContracts.PickVisualMedia()`) which requires ZERO permissions.
  - Document picker: Uses system storage access framework (`ActivityResultContracts.OpenDocument()`) requiring zero permissions.
  - Audio recording: Optional `RECORD_AUDIO` permission declared in `AndroidManifest.xml` with runtime permission check launcher in Compose for voice notes.
• Dependencies:
  - No new external third-party libraries required.
  - Uses existing Jetpack Compose, Material 3, Room, Coroutines, and AndroidX Navigation libraries already configured in Version Catalog.


9. POTENTIAL TECHNICAL RISKS & MITIGATIONS
--------------------------------------------------------------------------------
1. Risk: ViewModel Bloat.
   - Mitigation: Avoid putting chat logic inside `WorkspaceViewModel.kt`. Create a separate,
     focused `ChatViewModel.kt`.
2. Risk: LazyColumn Auto-Scroll Stutter on Fast Message Input.
   - Mitigation: Use `rememberLazyListState()` with `LaunchedEffect(messages.size)` to smoothly
     scroll to the latest item without recomposition jank.
3. Risk: Database Migration Corruption.
   - Mitigation: Write exhaustive unit test verifying `MIGRATION_3_4` and test in-memory database
     creation before applying to persistent database.
4. Risk: Stale Message Status.
   - Mitigation: Use Room `Flow<List<ChatMessageEntity>>` so message status updates (`SENDING` -> `SENT` -> `READ`)
     emit reactively and instantly re-render delivery ticks.
