1. EXISTING ARCHITECTURE AUDIT
--------------------------------------------------------------------------------
A comprehensive static analysis of the "My Workspace" Android codebase was performed
to map all existing assets, database entities, repositories, screens, and settings:

1.1 Chat Module & UI State:
• Screens:
  - `ChatsScreen.kt`: Conversation list with filter chips (All, Unread, Pinned,
    Direct, Channels), in-line search, and contact picker dialog.
  - `ConversationScreen.kt`: Chat thread with `MessageBubble`s, asymmetric corner styling,
    local status ticks (`LOCAL_PENDING`, `LOCAL_STORED`, `LOCAL_SENT`, `LOCAL_READ`),
    quoted reply banners, and `ChatInputBar` with attachment sheet & mic toggle.
  - `ConversationDetailScreen.kt`: Recipient profile, pin/mute toggles, media stats,
    and conversation deletion.
• State & ViewModel:
  - `ChatViewModel.kt`: Implements dedicated `ChatViewModel` exposing reactive StateFlows
    (`allConversations`, `filteredConversations`, `currentMessages`, `displayedMessages`,
    `draftMessageText`, `replyingToMessage`, `allContacts`).
  - `ChatViewModelFactory.kt`: Instantiates `ChatViewModel` with `IChatRepository`.
• Storage & Entities:
  - `ChatEntities.kt`: `ConversationEntity`, `ChatMessageEntity`, `MessageAttachmentEntity`,
    `ContactEntity`.
  - `ChatDao.kt`: 32 Room queries, atomic transaction `insertMessageAndUpdateConversation`.
  - `ChatRepository.kt`: Clean Room repository managing local threads and messages.

1.2 Task & Project Management Core:
• Database Version: 4 (`WorkspaceDatabase.kt`).
• Entities:
  - `ProjectEntity`: ID, name, description, categoryId, status ("Planning", "Active",
    "On Hold", "Completed", "Cancelled", "Archived"), priority, manualProgress, progress,
    weight, startDate, dueDate, createdAt, completedAt.
  - `TaskEntity`: ID, projectId, parentTaskId (hierarchical subtasks), title, description,
    status ("Backlog", "To Do", "In Progress", "On Hold", "In Review", "Completed",
    "Cancelled"), priority ("Low", "Medium", "High", "Urgent"), progress, dueDate, sortOrder.
  - `TaskDependencyEntity`: Directed graph edges (`taskId` depends on `dependsOnTaskId`)
    with BFS cycle detection, loop prevention, and blocked task calculation engine.
  - `ChecklistItemEntity`: Checklist items per task with completion toggles.
  - `CommentEntity`: Timestamped notes/comments on tasks.
  - `ProgressLogEntity`: Historical audit log of all progress modifications.
  - `ActivityLogEntity`: System-wide audit trail of all project, task, and dependency actions.
• Repository:
  - `WorkspaceRepository.kt`: Robust, transactional CRUD implementation with parent
    progress recalculation, hierarchy validation, and circular dependency detection.

1.3 Calendar, Deadlines & Reminders:
• `CalendarScreen.kt`: Observes `tasksWithDeadlines` (`dueDate != null`). Filters:
  - `overdueTasks`: `dueDate < now` and uncompleted.
  - `todayTasks`: `dueDate in now..(now + 86400000L)`.
  - `upcomingTasks`: grouped by timeline.
• Current Notification State:
  - In-app badges: `unreadNotifications = priorityTasks.size` in `AppTopBar.kt`.
  - Background system alerts (`AlarmManager` / `WorkManager`) are not yet scheduled
    as OS-level alarms; deadlines are currently tracked reactively in the database.

1.4 Memory & Notes:
• `NoteEntity`: Fields `id`, `projectId`, `taskId`, `title`, `content`, `isPinned`,
  `createdAt`, `updatedAt`, `archivedAt`.
• `NotesScreen.kt`: Rich note management with search, pin, and project linking.
• Finding: Currently there is no separate AI-specific memory store for user habits,
  preferences, or assistant conversation summaries. An `AiMemoryEntity` or specialized
  `NoteEntity` category can be integrated seamlessly.

1.5 Dependency Injection & Architecture Patterns:
• Architectural Pattern: Clean Architecture + MVVM + Repository Pattern.
• Dependency Injection: Constructor injection + `ViewModelProvider.Factory`.
• Single Activity: `MainActivity.kt` providing `WorkspaceViewModel` and `ChatViewModel`.

1.6 Permissions & Network Configuration:
• `AndroidManifest.xml`: Currently does NOT declare `<uses-permission android:name="android.permission.INTERNET" />`.
• `app/build.gradle.kts`:
  - `com.google.firebase:firebase-ai` (Firebase AI Logic SDK) is ALREADY included.
  - `com.squareup.retrofit2:retrofit`, `okhttp3`, and `moshi` are ALREADY included.
  - `secrets` plugin is configured to read from `.env` and `.env.example`.
• Platform Capabilities (`metadata.json`):
  - `"majorCapabilities": ["MAJOR_CAPABILITY_SERVER_SIDE_GEMINI_API"]` is enabled.

Detailed Findings:
• On-Device Small LLMs (Gemini Nano, Gemma 2B, SmolLM):
  - In theory private, but in practice on Android mobile, running LLM inference on CPU/NPU
    requires downloading 1.5GB to 3GB model weights over mobile data, causes memory exhaustion
    on devices with under 8GB RAM, drains battery quickly, and cannot reliably output structured
    JSON function calls to execute workspace tools.
• Cloud Aggregators (OpenRouter, HuggingFace Serverless):
  - Unstable quotas, frequent HTTP 429 throttles, and no long-term free SLA.
• Google Gemini 3.x Flash via Firebase AI Logic / Google AI Studio:
  - Official, high-reliability free tier: `gemini-3.8-flash` and `gemini-3.5-flash-lite`.
  - Allows up to 15 Requests Per Minute (RPM) and 1,500 Requests Per Day (RPD) for free.
  - Native function calling / tool declarations: The model can decide when to query tasks,
    create projects, or set reminders using strictly defined parameters.
  - Billing is NOT required for text generation on `gemini-3.8-flash` / `gemini-3.5-flash-lite`.
• Local Rule & Intent Command Engine:
  - The gold standard for zero-failure local computing: Instant, offline, zero battery cost,
    and 100% reliable for standard workspace requests ("show my tasks", "create task X",
    "what is overdue?", "complete task Y").


3. RECOMMENDED HYBRID ARCHITECTURE & JUSTIFICATION
--------------------------------------------------------------------------------
We recommend a **Dual-Engine Hybrid Architecture**:

1. Primary Brain (Online): **Google Gemini Flash (`gemini-3.8-flash`) via Free Tier**
   - Handles multi-turn natural language reasoning, intent disambiguation, complex
     scheduling inquiries, memory recall, and contextual summarization.
   - Utilizes native Function Calling with typed JSON schemas.
   - Cost: $0.00 (Standard Free Tier, no credit card required).

2. Secondary Brain & Offline Guardian: **Local Deterministic Command Engine**
   - Operates 100% on-device inside the app process.
   - Uses an intent grammar and regex entity extractor (`CommandMatcher`) backed by
     `WorkspaceRepository`.
   - Executes immediate actions without internet or cloud tokens.
   - Automatically takes over whenever:
     a) Device is offline or airplane mode is active.
     b) Cloud free quota (15 RPM / 1,500 RPD) is exhausted or returns HTTP 429.
     c) Network request times out (>10 seconds).
     d) User explicitly toggles "Offline Only AI Mode" in Settings.

Why This Hybrid Strategy is Superior:
• Zero Cost Guarantee: Never calls paid endpoints; fails gracefully to local commands.
• Resilience: The user's productivity command center NEVER stops functioning when
  offline or in a subway/flight.
• Privacy by Design: Users can inspect what tools are invoked and toggle cloud off at any time.


4. OFFLINE STRATEGY & FALLBACK GUARDIAN
--------------------------------------------------------------------------------
The Offline Strategy operates without any network connection using standard Android
Kotlin primitives:

1. Network Connectivity Monitoring:
   - `ConnectivityMonitor`: Listens to Android `ConnectivityManager` network callbacks.
   - Exposes `isOnline: StateFlow<Boolean>`.

2. Local Command Engine Grammar:
   Supports natural command variations:
   - Query Intents:
     * "tasks today", "what's on my plate today", "today's agenda" -> `getTodayTasks()`
     * "overdue", "late tasks", "missed deadlines" -> `getOverdueTasks()`
     * "pending tasks", "what's left to do", "to do list" -> `getPendingTasks()`
     * "status of [Project Name]", "how is [Project Name] going" -> `getProjectStatus(name)`
     * "recall [query]", "remember [query]", "notes about [query]" -> `searchMemory(query)`
   - Mutation Intents:
     * "add task [Title] to [Project]", "create task [Title]" -> `createTask(...)`
     * "complete task [Title]", "mark [Title] done" -> `completeTask(...)`
     * "remind me to [Title] tomorrow" -> `createReminder(...)`
     * "remember that [Note]" -> `saveMemory(...)`

3. Transparent UI Feedback:
   - When offline or when fallback occurs, the assistant response includes a subtle
     pill badge: `[⚡ Executed via Local Engine]` or `[Offline Mode]`.
   - Never leaves the user hanging with a generic "Connection failed" error.

6. WORKSPACE TOOL ARCHITECTURE
--------------------------------------------------------------------------------
All tools interact exclusively through a secure, validated `WorkspaceToolExecutor`
backed by `WorkspaceRepository`. The AI never generates raw SQL and never touches
the SQLite database directly.

6.1 Tool Specifications:

1. `getTodayTasks()`:
   - Parameters: none.
   - Behavior: Retrieves tasks where `dueDate` is within the current 24-hour calendar window.
   - Returns: Formatted list of task titles, priorities, parent projects, and status.

2. `getPendingTasks()`:
   - Parameters: `limit: Int = 10`, `projectId: String? = null`.
   - Behavior: Queries uncompleted tasks (`status != 'Completed' && status != 'Cancelled'`)
     sorted by priority and due date.
   - Returns: JSON array of task summaries.

3. `getOverdueTasks()`:
   - Parameters: none.
   - Behavior: Queries uncompleted tasks where `dueDate < System.currentTimeMillis()`.
   - Returns: List of overdue tasks with days overdue calculation.

4. `getProjectStatus(projectName: String)`:
   - Parameters: `projectName: String` (fuzzy matched against active projects).
   - Behavior: Retrieves project entity, calculates total tasks, completed tasks,
     overall progress percentage, and blocked task count.
   - Returns: Project overview summary.

5. `createTask(title: String, projectName: String?, priority: String?, dueDateMs: Long?)`:
   - Parameters: Validated task metadata.
   - Behavior: Resolves `projectId` (or creates/defaults to "General Workspace" project).
     Inserts `TaskEntity`, logs to `activity_logs`.
   - Returns: Confirmation of creation with ID.

6. `updateTask(taskIdOrTitle: String, newStatus: String?, newPriority: String?)`:
   - Parameters: Target task identifier and modified fields.
   - Behavior: Validates status against allowed enum values; triggers parent progress
     recalculation.
   - Returns: Updated task status.

7. `completeTask(taskIdOrTitle: String)`:
   - Parameters: Target task identifier.
   - Behavior: Checks if task has uncompleted subtasks or dependent tasks.
     If blocked by dependency -> Triggers warning or blocks.
     Sets status to "Completed", progress to 100%, records `ProgressLogEntity`.
   - Returns: Completion message.

8. `createReminder(taskTitle: String, dueDateMs: Long)`:
   - Parameters: Target task title and target epoch timestamp.
   - Behavior: Updates task's `dueDate` in SQLite database and logs activity.
   - Returns: Reminder confirmation.

9. `saveMemory(keyOrCategory: String, fact: String)`:
   - Parameters: Category/topic and text content.
   - Behavior: Stores into `notes` table or dedicated `ai_memories` table with
     timestamp and search index.
   - Returns: Confirmation that memory was committed to local storage.

10. `searchMemory(query: String)`:
    - Parameters: Search keywords.
    - Behavior: Performs text search across saved notes, memory facts, and recent activities.
    - Returns: Matching memory snippets.

6.2 Safety & Confirmation Gates:
- Read-only tools (`getTodayTasks`, `getPendingTasks`, `getOverdueTasks`, `getProjectStatus`,
  `searchMemory`): Execute automatically without user friction.
- Non-destructive mutations (`createTask`, `saveMemory`, `createReminder`): Execute with
  instant inline confirmation card.
- High-impact / Destructive actions (`deleteTask`, `completeTask` on blocked dependencies):
  Require interactive User Confirmation: The assistant posts an action proposal card in chat
  with [Confirm] and [Cancel] buttons before applying the SQLite transaction.


7. SECURITY & PRIVACY DESIGN
--------------------------------------------------------------------------------
1. Zero Sensitive Data Transmission:
   - Only task titles, notes, and user conversational queries are processed.
   - No user credentials, keystore data, or financial files are transmitted.
2. Cloud AI Consent Gate:
   - First-time prompt: When the user enters the AI Assistant chat thread, a clear
     dialog informs the user:
     "My Workspace AI Assistant uses Google's free Gemini API for natural language reasoning.
      Your data is never used to train public models. You can switch to 100% Offline Mode
      at any time in Settings."
   - Toggle in Settings: "Enable Cloud AI Assistant (Free Gemini Tier)".
3. Strict API Key Security:
   - No API keys are hardcoded in source files.
   - Managed via the Secrets Panel in AI Studio and injected into `BuildConfig` / `.env`.
   - In Firebase AI Logic mode, App Check attestation authenticates requests without
     client-exposed secrets.


8. STRICT COST PROTECTION DESIGN
--------------------------------------------------------------------------------
To completely eliminate any possibility of financial charges:

1. Zero Paid Endpoints:
   - Code strictly references `gemini-3.8-flash` and `gemini-3.5-flash-lite`.
   - Deprecated or paid-only models (such as `gemini-4-argon` requiring Blaze billing)
     are strictly forbidden in code.
2. No Automatic Paid Fallback:
   - If the free tier limit is reached (HTTP 429 Too Many Requests), the app NEVER
     attempts to route to a paid API.
   - It gracefully catches HTTP 429 and responds:
     "Free cloud AI quota reached for this minute. I have switched to the Local Engine
      to handle your request offline."
3. Local Throttle Tracker:
   - Client-side token and rate limiter ensures requests do not spam the API.
4. No Subscriptions or In-App Purchases:
   - Zero billing SDKs (no Google Play Billing, no Stripe, no external paywalls).

11. KNOWN LIMITATIONS & MITIGATIONS
--------------------------------------------------------------------------------
1. Limitation: Gemini Free Tier Rate Limits (15 Requests/Minute, 1,500 Requests/Day).
   - Mitigation: High-frequency bursts or rapid successive prompts automatically fall back
     to the instant Local Command Engine without error toasts or blocked workflows.
2. Limitation: Complex Reasoning Offline.
   - Mitigation: When offline, the assistant handles direct workspace commands (e.g.
     "What's overdue?", "Create task X") with 100% precision, but informs the user that
     complex conversational brainstorming requires an internet connection.
3. Limitation: Natural Language Ambiguity.
   - Mitigation: When a project or task name is ambiguous, the tool executor asks a clarifying
     question in chat rather than guessing or mutating the wrong record.
