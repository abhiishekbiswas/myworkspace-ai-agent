Read Tools:

2. getPendingTasks(projectId?: String, priority?: String):

6. MULTI-TURN CONVERSATION CONTEXT IMPLEMENTATION
--------------------------------------------------------------------------------
- History Tracking:
  * HybridAiCoordinator maintains an in-memory chronological list of AiConversationTurn objects per session.
  * Turn window is bounded to the last 20 turns (maxTurns = 20) to prevent unbounded memory growth while preserving conversational coherence.
- Turn Persistence:
  * Assistant responses and tool results are mapped back into ChatMessageEntity records and saved in Room ChatDatabase.
  * When a user returns to the AI Assistant conversation, previous chat history is loaded directly from ChatRepository.
- Disambiguation & Clarification:
  * When ambiguous queries are encountered, the assistant suggests options as candidate buttons in the UI (pendingClarification), allowing single-tap resolution by the user.

7. OFFLINE FALLBACK BEHAVIOR & RESILIENCE
--------------------------------------------------------------------------------
The HybridAiCoordinator implements strict priority routing rules:
1. User Toggle: If isCloudAiEnabled is false (toggled off by user), the request immediately routes to LocalCommandEngine with zero network access.
2. Network Connectivity: If isNetworkAvailable is false, the request immediately routes to LocalCommandEngine with a "📡 [Offline Mode Active]" status header.
3. Network Timeout: If the cloud provider does not respond within 30 seconds, execution is cancelled and automatically redirected to LocalCommandEngine.
4. HTTP 429 Quota Exhaustion: If the cloud provider returns HTTP 429 (RESOURCE_EXHAUSTED), isQuotaExhausted is set to true, and execution automatically completes via LocalCommandEngine with a "⚠️ [Free Quota Limit Reached — Switched to Offline Engine]" header.
5. Error Resilience: Any unexpected network or serialization exception automatically falls back to LocalCommandEngine, guaranteeing the user always receives a response.

8. COST PROTECTION & DUPLICATE ACTION PREVENTION (IDEMPOTENCY)
--------------------------------------------------------------------------------
- Idempotency Hash Fingerprinting:
  * Each tool execution creates a unique signature: "${toolCall.name}:${toolCall.arguments}".
  * HybridAiCoordinator maintains an executedActionSignatures set per conversation cycle.
  * If the model attempts to invoke the exact same write action multiple times within a single turn, the duplicate call is skipped and returns the previous cached result.
- Write Operations Guard:
  * Read operations (searches, stat queries) are executed freely.
  * Destructive or bulk write operations require confirmation or are strictly deduplicated.
